Car Infotainment UI

What if BMW’s iDrive NBT screen had been designed for fingers instead of a click wheel?

I started this years ago as a Bootstrap and jQuery sketch of my ideal car screen. Version 2 is a ground-up rewrite in plain HTML, CSS and JavaScript on a fixed 1280 × 480 canvas, the size of a 10.25" automotive display. It opens from file:// with no build step and runs on a Raspberry Pi in kiosk mode.

The rules: tap targets of at least 10 mm, one accent colour that carries all state, big glanceable numbers, and hardware keys that always get you home, even from inside CarPlay.

  • One event bus keeps the native screens, split screen and CarPlay in sync
  • Canvas maps built once into Path2D with Dijkstra routing over the street graph
  • Every setting works: accent colour, units, balance pad, brightness
  • Direct manipulation: drag the map, scrub tracks, swipe away warnings

Pokédex

A pocket-sized Pokédex with a Pokémon of the day, a silhouette quiz and a team builder, all running on PokeAPI.

  • 1,000+Pokémon
  • 8Explore hubs
  • 4Trainer tools
  • 5Detail tabs

Try the app below

Built on PokeAPI with Expo SDK 58 and Expo Router. It started as a list and a detail screen and grew into a full companion: a Home tab with a Pokémon of the day, eight Explore hubs of reference data, and four tools for planning a team.

TanStack Query caches everything, so moving between hubs is instant after the first load. On iOS 26 the tab bar is the native floating Liquid Glass; on Android it’s Material bottom navigation.

  • Home: Pokémon of the day, a daily fact, recent views and favourites
  • Explore: types, regions, moves, abilities, items, berries, TMs and natures
  • Tools: team matchups, stat calculator, silhouette quiz and compare
  • Detail screens with About, Stats, Evolution, Moves and Locations, plus Pokémon cries

Just In Case UI

An accessibility-first React component library. Yes, the name is a pun.

  • In progress
  • v0.3.0
  • 24 components
  • 0 runtime dependencies
  • WCAG 2.2 AA

Every component library I’ve shipped at work taught me the same lesson: accessibility added at the end never quite fits. Just In Case UI starts there instead, with each component specced in OpenSpec before any code is written.

It began with buttons, a text input and a dropdown. It’s now 24 components, from comboboxes and dialogs to pagination and toasts, each checked with axe. Instead of Storybook there’s a lightweight kitchen-sink app, running live below. Try it with only your keyboard.

  • Primary, secondary, tertiary: solid, outlined, text. Destructive gets its own red
  • Native elements first, then the matching WAI-ARIA pattern, with full keyboard support
  • Contrast is tested: every colour pair in the tokens is checked in CI
  • Calm by default: reduced motion and forced colours are both honoured
  • One variable per decision: every colour, radius and space is a --jic-* token
