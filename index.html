Car Infotainment UI

What if BMW’s iDrive NBT screen had been designed for fingers instead of a click wheel?

I started this years ago as a Bootstrap and jQuery sketch of my ideal car screen. Version 2 is a ground-up rewrite in plain HTML, CSS and JavaScript on a fixed 1280 × 480 canvas, the size of a 10.25" automotive display. It opens from file:// with no build step and runs on a Raspberry Pi in kiosk mode.

The rules: tap targets of at least 10 mm, one accent colour that carries all state, big glanceable numbers, and hardware keys that always get you home, even from inside CarPlay.

  • One event bus keeps the native screens, split screen and CarPlay in sync
  • Canvas maps built once into Path2D with Dijkstra routing over the street graph
  • Every setting works: accent colour, units, balance pad, brightness
  • Direct manipulation: drag the map, scrub tracks, swipe away warnings

Code on GitHub (opens in new tab) Vanilla JS, Canvas, CSS color-mix(), Web Speech

Pokédex

A React Native Pokédex that stays smooth while scrolling through the entire National Dex.

Built on PokeAPI with Expo SDK 58 and Expo Router. The list is a two-column grid tinted by each Pokémon’s primary type. Only on-screen tiles render, pages of 60 load as you scroll, and each tile fetches its own types when it appears.

Detail screens carry About, Base Stats with type defences, Evolution and Moves tabs. On iOS 26 the tab bar is the native floating Liquid Glass; on Android it’s Material bottom navigation.

  • FlashList for virtualized tiles
  • TanStack Query for fetching and caching
  • Native tabs for the Pokédex, favourites, types, regions and search
  • Jest tests on the formatting and region logic

Code on GitHub (opens in new tab) React Native 0.88, Expo Router, FlashList

    Just In Case UI

    An accessibility-first React component library. Yes, the name is a pun.

    Every component library I’ve shipped at work taught me the same lesson: accessibility added at the end never quite fits. Just In Case UI starts there instead, with each component specced in OpenSpec before any code is written.

    The first set is buttons, text input and dropdown. Instead of Storybook, components are shown in a lightweight kitchen-sink app. The panel here is a small taste of that, so try it with only your keyboard.

    • Primary, secondary, tertiary: solid, outlined, text
    • Destructive actions get their own red
    • Labels, hints and errors wired up for screen readers
    • Full keyboard support on the dropdown

    In progress React, TypeScript, OpenSpec
